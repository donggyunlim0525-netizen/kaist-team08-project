# Spec — 원치 않는 성분 거르기 (청담음료)

- 작성: 이윤표 · 2026-10-29
- 제품: 청담음료 (팀 8조, 웰니스 유저용 음료 성분 비교)
- 만든 방법: `/grill-me` 세션 1라운드(8문항)에서 정한 내용을 정리함
- 코드: [`prototypes/lee-yunpyo/`](../../prototypes/lee-yunpyo/)

## 1. WhyTree에서 어느 노드인가

[`docs/whytree/lee-yunpyo.md`](../whytree/lee-yunpyo.md)의 노드 **`원치 않는 성분 거르기`** [아직 안 함].

```
내 몸에 맞는 음료로 건강한 일상
  └ 고르는 시간 아끼기
      └ 성분표 대신 읽어주기
          └ 원치 않는 성분 거르기   ← 이 스펙
```

걸러진 이유를 보여주는 부분(아래 3-5단계)은 `믿고 마시기`에도 도움이 된다.

## 2. 누구를 위한 것이고, 문제는 언제 생기나

- **누구:** 성분을 따지는 30~40대 직장인 여성. 웰니스 F&B에 꾸준히 돈을 쓴다. (PROJECT.md의 청담음료 페르소나)
- **언제:** 편의점 음료 냉장고 앞에서 폰으로 **30초 안에** 음료 하나를 고를 때.
- **무엇이 문제인가:** "제로"라고 써 있어도 액상과당, 카페인, 인공감미료가 들어 있을 수 있다. 확인하려면 병 뒷면의 작은 원재료 글씨를 하나씩 읽어야 한다. 30초 안에는 못 한다.

## 3. 사용자가 하는 일 (단계별)

1. 사용자가 페이지를 연다. 음료 목록이 보인다. 맨 위에 "피하고 싶은 성분" 칩 4개가 있다.
2. 사용자가 칩을 하나 이상 누른다. 예: `액상과당`, `카페인`.
3. 목록이 바로 줄어든다. 고른 성분이 원재료에 있는 제품은 목록에서 빠진다.
4. 목록 위에 "N개 제외됨 · 이유 보기"가 보인다.
5. 사용자가 "이유 보기"를 누르면, 빠진 제품마다 **걸린 원재료 단어**(예: "고과당옥수수시럽 → 액상과당")가 보인다.
6. 원재료 정보가 없는 제품은 "원재료 정보 없음" 영역에 따로 보인다. 필터를 통과한 것으로 치지 않는다.
7. 사용자가 검색창에 제품명을 쓰면 남은 목록 안에서 이름으로 좁혀진다.
8. 사용자가 칩을 다시 누르면 그 성분 필터가 꺼지고 목록이 돌아온다.

## 4. 판정 규칙 (약사 동의어 사전)

판정은 규칙 기반 키워드 매칭이다. 사전 파일: `prototypes/lee-yunpyo/data/dictionary.js`. 원재료 텍스트를 쉼표·괄호로 나눠 **항목** 단위로 본다. 각 항목에서 공백을 지운 뒤, 아래 단어가 들어 있으면 그 그룹에 걸린 것으로 본다.

| 그룹 | 걸리는 단어 (P0) | 걸리지 않게 할 단어 (예외) |
|---|---|---|
| 액상과당 | 액상과당, 과당시럽, 고과당옥수수시럽, 고과당콘시럽, 옥수수시럽, 콘시럽, 과당포도당액, 포도당과당액, HFCS | — |
| 카페인 | 카페인, 커피, 녹차추출물, 녹차추출분말, 홍차추출물, 마테, 과라나, 콜라넋 | 디카페인, 카페인제거 |
| 인공감미료 | 아스파탐, 수크랄로스, 아세설팸칼륨, 아세설팸K, 사카린, 네오탐, 어드밴탐 | — |
| 당알코올 | 에리스리톨, 말티톨, 자일리톨, 소비톨, 솔비톨, 만니톨, 락티톨, 이소말트 | — |

규칙:
- 예외 단어가 든 항목은 그 그룹에서 통째로 세지 않는다. 예: "디카페인커피추출액" 항목은 카페인으로 세지 않는다.
- 한 제품이 여러 그룹에 걸리면 걸린 그룹을 모두 보여준다.
- 사전이 틀리면 사전 한 줄만 고친다. 코드는 고치지 않는다.

## 5. 데이터

- **실제 데이터:** 식품안전나라 C002(품목제조보고)의 `RAWMTRL_NM`(원재료), `PRDLST_NM`(제품명), `BSSH_NM`(업체명), `PRDLST_DCNM`(식품유형).
- **받는 방법:** 노트북에서 `scripts/fetch_c002.py`를 한 번 실행한다. API 키는 `.env`의 `FOODSAFETY_API_KEY`에서 읽는다. 결과는 `data/products.js`(정적 스냅샷)로 저장한다.
- **브라우저 코드에는 키를 넣지 않는다.** 페이지는 스냅샷 파일만 읽는다.
- **범위:** 음료류만. `PRDLST_DCNM`이 탄산음료, 혼합음료, 과·채음료, 과·채주스, 액상차, 커피, 두유류, 발효음료류, 기타음료 중 하나인 것만 남긴다.
- **현재 프로토타입 상태:** 빌드 환경에서 식품안전나라 API에 접속하지 못했다. 그래서 프로토타입은 **가상 제품 24개로 된 데모 데이터**(`data/demo-products.js`)로 동작한다. 화면 상단에 "데모 데이터(가상 제품)" 표시를 한다. 실제 스냅샷 파일이 있으면 페이지가 그 파일을 먼저 읽는다.

## 6. AI 모델

- **P0에서는 AI 모델을 쓰지 않는다.**
- 이유: 같은 원재료에 같은 결과가 나와야 사용자가 믿는다. 약사가 사전을 책임질 수 있다. 오판이 생기면 사전 한 줄로 고친다.
- 실패할 때: 해당 없음. 대신 사전이 놓치는 경우(새 감미료 이름 등)가 실패다. 이 경우 제품은 "통과"로 보인다. 그래서 화면 하단에 "원재료 표시를 기준으로 한 자동 분류입니다. 최종 확인은 제품 포장의 원재료 표시를 보세요."를 항상 보여준다.
- P2에서 LLM을 쓴다면: 사전에 없는 원재료 단어만 LLM에 보내 그룹 후보를 받고, **약사가 승인한 것만 사전에 추가**한다. LLM이 실패하거나 응답이 없으면 사전만으로 판정한다.

## 8. 범위 밖

- 영양성분 수치(당 g, kcal)로 거르기. 이 스펙은 원재료 표시만 본다.
- 건강 효과나 질병에 대한 말. "몸에 나쁘다" 같은 표현을 쓰지 않는다. 사용자가 피하고 싶다고 고른 것을 걸러줄 뿐이다.
- 제품 순위, 추천, 가격, 파는 곳.
- 회원 가입과 로그인.
- 분말·정제·건강기능식품.

## 9. 손으로 하는 확인 (3개)

1. **카페인 + 예외:** `카페인` 칩만 켠다. "커피"가 원재료에 있는 제품은 빠지고, "디카페인커피"만 있는 제품은 남아야 한다. "이유 보기"에 빠진 제품의 걸린 단어가 보여야 한다.
2. **동의어:** `액상과당` 칩만 켠다. 원재료에 "액상과당"이라는 글자는 없고 "고과당옥수수시럽"만 있는 제품도 빠져야 한다.
3. **정보 없음:** 칩을 4개 다 켠다. 원재료가 비어 있는 제품은 남은 목록에 없어야 하고, "원재료 정보 없음" 영역에 보여야 한다. 칩을 다 끄면 제외 0개, 처음 목록 수와 같아야 한다.

## 10. 빌드 후 바뀐 것

- **5. 데이터**에 "현재 프로토타입 상태" 줄을 추가했다. 빌드 중에 빌드 환경에서 식품안전나라 API에 접속할 수 없다는 것을 알았다. 그래서 데모 데이터와 실제 데이터 스크립트를 나눠고, 스크립트 실행을 P1로 내렸다.
- **5. 데이터**의 파일 형식을 `.json`에서 `.js`로 바꿨다. 브라우저에서 `index.html`을 파일로 바로 열면 `.json`을 읽을 수 없다. 설치 없이 열리게 한다는 결정(그릴 Q8)을 지키려고 형식을 바꿨다.
- **4. 판정 규칙**을 "원재료 텍스트 전체에서 단어 찾기"에서 "쉼표·괄호로 나눈 항목마다, 공백을 지우고 찾기"로 바꿨다. 첫 구현에서 확인 1과 2가 실패했다.
  - 확인 1 실패: 예외 단어 "디카페인"만 지웠더니 "디카페인커피추출액"에서 "커피"가 남아 카페인으로 걸렸다.
  - 확인 2 실패: "고과당 옥수수 시럽"처럼 띄어 쓴 원재료가 "고과당옥수수시럽"과 맞지 않았다.
- 확인 3은 처음부터 통과했다.
