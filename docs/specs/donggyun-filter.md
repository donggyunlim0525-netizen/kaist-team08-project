# 사양서 — 조건 필터로 좁히기

- 작성: 임동균 (donggyun) · 2026-10-28
- 피처: 조건 필터로 좁히기
- WhyTree 노드: 조건 필터로 좁히기 → 내 기준에 맞는 음료 발견하기 → 후회 없이 선택하기
- 결정 방법: /grill-me 세션 (2026-10-28, 질문 6개)

## 1. 누구를 위해, 언제 문제가 생기나

- 대상: 건강 관리에 관심이 많고 제품 선택에 시간과 비용을 투자하는 30~40대 중상위 소득 여성 (청담음료 MVP 핵심 타깃).
- 상황: 온라인에서 매일 마실 음료를 고르기 전.
- 문제: 제품마다 성분표 형식이 달라 일일이 읽고 비교하는 데 비용이 크다. "당류는 이 정도까지만" 같은 자기 기준은 있는데, 그 기준을 제품 목록에 적용할 도구가 없어 감과 브랜드 인지도에 의존해 고르고, 산 뒤에 성분을 보고 후회한다.

## 2. 사용자 행동 흐름

1. 사용자가 필터 화면에 들어온다. 조건 3종이 모두 "제한 없음"이고, 전체 제품이 당류 낮은 순으로 보인다. 결과 수가 표시된다.
2. 당류 칩 중 하나를 누른다 (0·5·10g 이하, 100ml 기준). 결과가 즉시 좁혀진다.
3. 단백질 칩 (10·15·20g 이상, 1회 제공량 기준)과 "카페인 없음" 토글을 추가로 켠다. 조건은 전부 AND로 적용된다.
4. 결과 카드에서 제품별 당류·단백질·카페인 값을 확인한다. 성분 정보가 없는 제품은 결과에서 빠지고, 결과 아래에 "정보가 없어 제외된 제품 N개"가 표시된다 (펼치면 어떤 제품인지 볼 수 있다).
5. 모든 조건을 만족하는 제품이 0개면, 빈 화면 대신 조건 완화 제안을 본다: "당류 조건을 풀면 3개"처럼 조건별 해제 시 결과 수가 표시되고, 누르면 그 조건만 해제된다.
6. 마음에 드는 제품을 확인하고 탐색을 마친다 (상세 보기와 구매는 이 피처의 범위 밖).

## 3. 우선순위

### P0 — 반드시 동작
- 샘플 제품 12개 내장 데이터: 당류·단백질·카페인 값을 가지며, 정보 없음(null) 케이스 1개 이상, 결과 0개 조합이 실제로 발생하는 분포를 포함한다. 프로토타입용 가상 제품이며 실제 제품의 성분값이 아니다.
- 조건 3종 AND 필터
  - 당류 상한 칩: 제한 없음 / 0g 이하 / 5g 이하 / 10g 이하 (100ml 기준)
  - 단백질 하한 칩: 제한 없음 / 10g 이상 / 15g 이상 / 20g 이상 (1회 제공량 기준)
  - 카페인 없음 토글: 카페인 0mg인 제품만 통과
- 결과 목록: 제품명과 당류·단백질·카페인 값 표시, 당류 낮은 순 고정 정렬. 단, 조건이 없을 때의 기본 목록에서는 당류 정보가 없는 제품을 맨 뒤에 둔다.
- 결과 수 표시
- null 처리: 조건이 걸린 성분이 null인 제품은 제외하고, "정보가 없어 제외된 제품 N개" 안내 + 펼쳐보기. 단, 다른 조건에서 이미 탈락한 제품은 이 개수에 넣지 않는다 (정보가 없어서 빠진 것만 센다).
- 결과 0개: 조건 완화 제안 (조건별 해제 시 결과 수 표시, 클릭하면 해당 조건만 해제)
- 조건 초기화 버튼

### P1 — 시간 되면
- 칼로리 상한 조건 추가
- 원재료 제외 조건 (제품별 원재료 목록 데이터가 필요해 데이터 준비 비용이 큼)
- 내 조건 조합 저장

### P2 — 나중
- 자연어 입력 → AI 조건 변환 (아래 5번의 폴백 규칙 적용)
- 정렬 전환 UI (당류순/단백질순) — WhyTree의 '랭킹·정렬로 비교하기' 노드와 함께 다룬다
- 식약처 식품영양성분 DB 실제 연동

## 4. 범위 밖

- 제품 상세·성분 해설 화면 (별도 WhyTree 노드)
- 구매·결제·구매처 링크
- 목표별 탐색 (별도 WhyTree 노드)
- 출시 알림 신청 (별도 WhyTree 노드)
- 성분 점수 (WhyTree 점선 상자 — 아직 하지 않는 일)

## 5. AI 사용

- 이 피처는 AI 모델을 쓰지 않는다. 필터는 구조화된 수치에 대한 결정적인 계산이어야 한다: 사용자가 건 상한을 넘는 제품이 모델의 해석으로 새어 나오면, "기준 있게"라는 청담음료의 약속 자체가 깨진다.
- 모델 오류 시 동작: 해당 없음. 단, P2의 자연어 변환을 도입할 경우의 규칙을 미리 정한다 — 변환 결과는 칩 상태로 먼저 보여주고 사용자가 확인해야만 적용한다. 해석에 실패하거나 확신이 낮으면 어떤 조건도 임의로 적용하지 않고 칩 UI로 되돌린다.

## 6. 수동 검증 방법

1. 당류 5g 이하 + 단백질 15g 이상 + 카페인 없음을 모두 켜고, 남은 제품 전원이 세 조건을 실제로 만족하는지 카드의 값과 하나씩 대조한다.
2. 정보 없음 제품이 결과에서 빠졌는지, "제외된 제품 N개"의 N이 실제 null 제품 수와 같은지 센다.
3. 결과가 0개가 되는 조합을 만들고, 완화 제안의 "풀면 N개" 숫자가 실제로 그 조건 하나만 풀었을 때의 결과 수와 일치하는지 확인한다.
