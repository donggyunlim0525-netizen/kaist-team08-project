# 사양서 — 성분 비교

- 작성: 장래희 (raehee) · 2026-10-29
- 피처: 성분 비교 (제품 2~3개를 나란히 놓고 성분 차이를 보기)
- WhyTree 노드: 성분 비교 → 상품 차이·출처 확인 → 성분 이해와 선택의 확신 → 내 기준에 맞는 음료를 빠르고 확신 있게 선택
- 결정 방법: 간이 질문 3개 (기능 선택, 데이터, 구현 형태)로 정했다. 나머지 항목은 제안 기본값이며, 구현 중 바뀐 점은 맨 아래 변경 기록에 남긴다. 정식 /grill-me 세션은 거치지 않았다.

## 1. 누구를 위해, 언제 문제가 생기나

- 대상: 성분을 따져서 음료를 고르는 30~40대 직장인 (청담음료 웰니스 유저).
- 상황: 후보를 2~3개로 줄였는데 마지막 한 개를 정하지 못할 때. 제품 페이지마다 성분표 위치와 형식이 달라서, 탭을 오가며 숫자를 눈으로 맞춰 봐야 한다.
- 문제: 어느 쪽이 얼마나 다른지 한눈에 안 보인다. 그래서 "지금 고른 게 최선인가?" 하는 확신이 서지 않고, 결국 인기 순위에 기대어 고른다.

## 2. 사용자 행동 흐름

1. 사용자가 제품 목록(샘플 12개)을 본다. 각 카드에 "비교에 담기" 버튼이 있다.
2. 제품 2개를 담으면 화면 아래에 "비교하기 (2)" 바가 나타난다. 최대 3개까지 담을 수 있다. 4번째를 담으려 하면 "최대 3개까지 비교할 수 있어요" 안내가 나오고 담기지 않는다.
3. "비교하기"를 누르면 나란히 놓은 비교표가 나온다. 행은 1회 제공량, 칼로리, 당류, 단백질, 카페인이다.
4. 칼로리·당류·카페인 행에는 "가장 낮음", 단백질 행에는 "가장 높음" 표시가 붙는다. 값이 같으면 같은 표시가 함께 붙고, 모두 같으면 "동일"로 표시한다.
5. 각 행 아래에 한 줄 요약이 나온다. 예: "당류는 카카오 프로틴 라떼가 4g 더 적어요".
6. 값이 없는 칸은 "정보 없음"으로 보이고, 그 칸은 "가장 낮음/높음" 계산과 요약에서 빠진다.
7. 비교표에서 제품을 빼도 2개 이상 남아 있으면 비교 화면이 유지되고, 1개만 남으면 목록 화면으로 돌아간다. "전부 비우기"를 누르면 바로 목록 화면으로 돌아간다. (구매와 상세 보기는 이 피처의 범위 밖)

## 3. 우선순위

### P0 — 반드시 동작
- 샘플 제품 12개 내장 데이터. 칼로리·당류(100ml 기준), 단백질·카페인(1회 제공량 기준), 1회 제공량(ml)을 가진다. 값이 없는(null) 제품 2개 이상, 모든 값이 같은 제품 쌍 1개 이상을 포함한다. 가상 제품이며 실제 제품의 성분값이 아니다.
- 제품 목록 + "비교에 담기" / "담기 취소"
- 최대 3개 제한, 4번째 담기 시 안내
- 비교하기 바 (2개 이상일 때만 활성)
- 비교표 (제품 2~3개 열, 위 5개 행)
- "가장 낮음 / 가장 높음 / 동일" 표시 (동점은 모두 표시)
- 행별 한 줄 요약 (두 값 이상이 있을 때만)
- null 처리: "정보 없음" 표시, 계산에서 제외
- 비교에서 제품 빼기, 전부 비우기
- 화면 어딘가에 "가상 샘플 데이터이며 실제 제품 성분이 아닙니다" 안내

### P1 — 시간 되면
- 제품 이름 검색
- 비교 결과를 링크로 공유 (URL에 담은 제품 id 저장)
- 가격 행 추가

### P2 — 나중
- 식약처 식품안전나라 API 연동으로 실제 성분표 사용
- 성분별 해설 문구 ("당류 5g은 어느 정도인가요?")
- 출처 표시와 연결 (WhyTree의 '출처 표시' 노드와 함께 다룬다)

## 4. 범위 밖

- 조건 필터, 성분 필터 (팀원이 맡은 WhyTree 노드)
- 카테고리 탐색
- 출처 표시 (별도 WhyTree 노드)
- 구매, 결제, 구매처 링크
- 로그인, 비교 목록 저장

## 5. AI 사용

- 이 피처는 AI 모델을 쓰지 않는다. 비교표의 숫자와 "가장 낮음/높음" 판정은 결정적인 계산이어야 한다. 모델이 숫자를 해석하거나 요약을 지어내면 "성분 이해와 선택의 확신"이라는 목적이 깨진다.
- 모델 오류 시 동작: 해당 없음. 한 줄 요약도 모델이 아니라 정해진 문장 틀에 숫자를 넣어 만든다.

## 6. 수동 검증 방법

샘플 제품 번호는 `prototypes/raehee/data.js`의 목록 순서를 따른다.

1. **비교 계산 확인:** "카카오 프로틴 라떼", "오트 바닐라 프로틴", "단백질 요거트 드링크"를 담고 비교한다. 당류는 4 / 6 / 8g이므로 카카오 프로틴 라떼에 "가장 낮음", 단백질은 20 / 15 / 18g이므로 카카오 프로틴 라떼에 "가장 높음"이 붙는지, 카페인은 10 / 0 / 0mg이므로 오트 바닐라와 요거트 둘 다 "가장 낮음"이 붙는지 카드의 값과 대조한다.
2. **정보 없음 처리:** "레몬 전해질 워터"(단백질 없음)와 "사과 식초 스파클링"(칼로리·당류 없음)과 "카카오 프로틴 라떼"를 담고 비교한다. 없는 칸이 "정보 없음"으로 보이는지, 그 칸이 "가장 낮음/높음"과 한 줄 요약에서 빠졌는지 확인한다.
3. **동일 값과 3개 제한:** "라임 제로 스파클링"과 "보리차 제로"를 담으면 칼로리·당류·단백질·카페인이 모두 "동일"로 나오는지 확인한다. 이어서 제품을 3개까지 담은 뒤 4번째를 담으려 할 때 안내가 나오고 담기지 않는지 확인한다.
