## 1. 누구를 위해, 언제 문제가 생기나

- 대상: 성분을 따져서 음료를 고르는 30~40대 직장인 (청담음료 웰니스 유저).
- 상황: 후보를 2~3개로 줄였는데 마지막 한 개를 정하지 못할 때. 제품 페이지마다 성분표 위치와 형식이 달라서, 탭을 오가며 숫자를 눈으로 맞춰 봐야 한다.
- 문제: 어느 쪽이 얼마나 다른지 한눈에 안 보인다. 제품마다 용량도 달라서 숫자를 그대로 비교하면 오해하기 쉽다. 그래서 "지금 고른 게 최선인가?" 하는 확신이 서지 않고, 결국 인기 순위에 기대어 고른다.

## 2. 사용자 행동 흐름

1. 사용자가 제품 목록(샘플 12개)을 본다. 각 카드에 1회 제공량 기준의 칼로리·당류·단백질·카페인이 보이고, "비교에 담기" 버튼이 있다.
2. 제품 2개를 담으면 화면 아래에 "비교하기 (2)" 바가 나타난다. 최대 3개까지 담을 수 있다. 4번째를 담으려 하면 "최대 3개까지 비교할 수 있어요" 안내가 나오고 담기지 않는다.
3. "비교하기"를 누르면 나란히 놓은 비교표가 나온다. 행은 1회 제공량(ml), 칼로리, 당류, 단백질, 카페인이다. 모든 수치는 1회 제공량 기준이다.
4. 칼로리·당류·카페인 행에는 "가장 낮음", 단백질 행에는 "가장 높음" 표시가 붙는다. 값이 같은 제품에는 같은 표시가 함께 붙고, 모두 같으면 "동일"로 표시한다. 어느 쪽이 "좋다"는 평가는 하지 않는다.
5. 각 행 아래에 한 줄 요약이 나온다. 예: "당류: 카카오 프로틴 라떼 쪽이 가장 낮아요 (가장 높은 제품과 12.4g 차이)".
6. 값이 없는 칸은 "정보 없음"으로 보이고, 그 칸은 "가장 낮음/높음" 계산과 요약에서 빠진다.
7. 비교표에서 제품을 빼도 2개 이상 남아 있으면 비교 화면이 유지되고, 1개만 남으면 목록 화면으로 돌아간다. "전부 비우기"를 누르면 바로 목록 화면으로 돌아간다. (구매와 상세 보기는 이 피처의 범위 밖)

## 3. 우선순위

### P0 — 반드시 동작
- 샘플 제품 12개 내장 데이터. 칼로리·당류(100ml 값), 단백질·카페인(1회 제공량 값), 1회 제공량(ml)을 가진다. 값이 없는(null) 제품 2개 이상, 모든 값이 같은 제품 쌍 1개 이상, 100ml 값은 다르지만 1회 제공량 기준으로는 같아지는 쌍 1개 이상을 포함한다. 가상 제품이며 실제 제품의 성분값이 아니다.
- 1회 제공량 기준 환산: 칼로리·당류 = 100ml 값 × 제공량(ml) ÷ 100 (소수 첫째 자리까지)
- 제품 목록 + "비교에 담기" / "담기 취소"
- 최대 3개 제한, 4번째 담기 시 안내
- 비교하기 바 (2개 이상일 때만 활성)
- 비교표 (제품 2~3개 열, 위 5개 행)
- "가장 낮음 / 가장 높음 / 동일" 표시 (동점은 모두 표시)
- 행별 한 줄 요약 (비교할 값이 2개 이상일 때만)
- null 처리: "정보 없음" 표시, 계산에서 제외
- 비교에서 제품 빼기, 전부 비우기
- 화면 상단에 "가상 샘플 데이터이며 실제 제품 성분이 아닙니다" 안내

### P1 — 시간 되면 (이 순서로)
1. 제품 이름 검색
2. 비교 결과를 링크로 공유 (URL에 담은 제품 id 저장)
3. 감미료 종류 행 (제로 음료 사용자에게 중요하지만 데이터 준비 비용이 크다)
4. 가격 행

### P2 — 나중
- 식약처 식품안전나라 API 연동으로 실제 성분표 사용 (이때 출처 표시와 함께 다룬다. 식약처 데이터는 100ml 기준이 많아 환산 규칙을 다시 확인한다)
- 성분별 해설 문구 ("당류 5g은 어느 정도인가요?"). 정해진 문구만 사용한다
- 사용자가 "내 기준"(예: 당류는 낮을수록 좋음)을 고르면 그 기준으로 강조
- 휴대폰용 세로 카드형 비교

## 4. 범위 밖

- 조건 필터, 성분 필터 (팀원이 맡은 WhyTree 노드)
- 카테고리 탐색
- 출처 표시 (별도 WhyTree 노드. 실제 데이터를 붙이는 P2에서 다룬다)
- 구매, 결제, 구매처 링크
- 로그인, 비교 목록 저장
- "추천", "좋음/나쁨" 같은 평가 표시

## 5. AI 사용

- 이 피처는 AI 모델을 쓰지 않는다. 비교표의 숫자와 "가장 낮음/높음" 판정은 결정적인 계산이어야 한다. 모델이 숫자를 해석하거나 요약을 지어내면 "성분 이해와 선택의 확신"이라는 목적이 거꾸로 깨진다.
- 한 줄 요약은 모델이 쓰지 않고, 정해진 문장 틀에 계산된 숫자를 넣어 만든다.
- 모델 오류 시 동작: 해당 없음. 나중에 해설(P2)이 필요해져도 정해진 문구만 쓴다.

## 6. 수동 검증 방법

제품 이름은 `prototypes/jang-raehee/data.js`의 샘플과 같다. 카드와 비교표의 숫자는 모두 1회 제공량 기준이다.

1. **비교 계산 확인:** "카카오 프로틴 라떼", "오트 바닐라 프로틴", "단백질 요거트 드링크"를 담고 비교한다. 당류는 10 / 15 / 22.4g이므로 카카오 프로틴 라떼에 "가장 낮음", 단백질은 20 / 15 / 18g이므로 카카오 프로틴 라떼에 "가장 높음", 카페인은 10 / 0 / 0mg이므로 오트 바닐라와 요거트 둘 다 "가장 낮음"이 붙는지 카드의 값과 하나씩 대조한다.
2. **정보 없음 처리:** "레몬 전해질 워터"(단백질 없음)와 "사과 식초 스파클링"(칼로리·당류 없음)과 "카카오 프로틴 라떼"를 담고 비교한다. 없는 칸이 "정보 없음"으로 보이는지, 그 칸이 "가장 낮음/높음"과 한 줄 요약에서 빠졌는지 확인한다.
3. **동일 값과 3개 제한:** "라임 제로 스파클링"과 "보리차 제로"를 담으면 칼로리·당류·단백질·카페인이 모두 "동일"로 나오는지 확인한다. 이어서 제품을 3개까지 담은 뒤 4번째를 담으려 할 때 안내가 나오고 담기지 않는지 확인한다.
4. **1회 제공량 환산:** "석류 비타 워터"(500ml, 100ml당 당류 3g)와 "오트 바닐라 프로틴"(250ml, 100ml당 당류 6g)을 담는다. 100ml 값은 다르지만 한 병 기준 당류는 둘 다 15g이므로, 당류 행이 "동일"로 나오는지 확인한다.

## 7. 성공 확인: 30초 테스트 (Q6)

- 방법: 처음 보는 사람 1~2명에게 "카카오 프로틴 라떼 / 오트 바닐라 프로틴 / 단백질 요거트 드링크" 비교표를 보여 주고 "어느 쪽이 당류가 가장 낮아요?"라고 묻는다. 설명은 하지 않는다.
- 통과 기준: 30초 안에 "카카오 프로틴 라떼"라고 답한다.
- 결과: 아직 실시하지 않았다. 실시하면 이 칸과 변경 기록에 적는다.
